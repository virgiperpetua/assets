## Gelato Messina: production & stock tracker

Role: sole developer · Stack: JavaScript, SQL/database, UI built for shop-floor use · Status: live, in daily use

- Image slot `gelato-cs-hero` — Drop a screenshot or floor photo of the tool in use

I manage a Gelato Messina store — a high-volume operation where flavours have to be churned fresh, stock has to be tracked precisely, and decisions happen fast, on a floor, not at a desk.

Knowing which flavours needed churning next, how much stock was actually left, and when to start production meant either walking the floor constantly or pulling out a phone mid-shift. Both interrupted the actual work of running the store, and decisions ended up slower and more reactive than they needed to be.

Goal: a single screen that answers "what needs churning, what's running low, when should production start" without a phone. I designed, built, and shipped it alone, alongside full-time store management and study — so the constraint was as much time and focus as it was technical.

A lightweight application that tracks flavour stock levels, flags which flavours need churning, and times the churner's production runs — built to sit on a shared screen or tablet on the floor, not to be opened and closed like a report.

Flavour-by-flavour stock status, consumption tracking to inform what to produce next, and timing support for the churn cycle itself — the three decisions that used to require either memory or a phone call.

I kept the interface deliberately simple — large, glanceable status rather than dense tables — because the environment is a working kitchen floor, not an office. Data is structured so stock and production data stay in sync without manual re-entry.

Before: checking a phone or walking the floor to judge stock and production timing. After: a glance at a shared screen gives the same answer, faster, without leaving the task at hand.

The tool is in daily use at the store. I haven't run a formal measurement study, so I won't claim a number — but the intended and observed effect is fewer phone-checks, faster production decisions, and less dependence on any one person's memory of stock levels.

I'd like to add simple historical trends — which flavours consistently run low on which days — so production becomes a little predictive instead of purely reactive. That's the natural next step toward the automation work I'm exploring now.
